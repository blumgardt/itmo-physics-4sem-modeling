# Физика и код: дифракция Фраунгофера

## Что моделируется

**Дифракция** — это огибание световой волной препятствия. Если поставить на пути света тонкий объект (например, пластинку с прорезанной щелью) и наблюдать свет на экране далеко позади него, то вместо чёткой "тени" получится картина из светлых и тёмных полос — это и есть дифракционная картина.

**Дифракция Фраунгофера** — частный случай: экран наблюдения находится **очень далеко** от объекта (так называемая *дальняя зона*). В этом режиме дифракционная картина математически связана с самим объектом простым и красивым способом — через двумерное **преобразование Фурье**.

---

## Шаг 1. Амплитудная маска `t(x, y)` — "как выглядит объект"

**Физика:** Любой плоский объект можно описать функцией `t(x, y)`, которая в каждой точке плоскости говорит, какая доля волны проходит сквозь объект:
- `t = 1` — точка полностью прозрачна,
- `t = 0` — точка полностью непрозрачна,
- промежуточные значения — частичная прозрачность.

Это и есть **амплитудное пропускание**. Прямоугольная щель — это `t = 1` внутри прямоугольника и `0` снаружи. Круг — `t = 1` внутри круга. Решётка — серия полос.

**В коде:** функция `buildAperture` (`main.go`) заполняет массив `complex128` длиной `N²` нулями и единицами:

```go
case apRect:
    if math.Abs(x) <= halfW && math.Abs(y) <= halfH {
        v = 1
    }
case apCircle:
    if x*x + y*y <= halfW*halfW {
        v = 1
    }
```

Для каждой формы (`apRect`, `apCircle`, `apDoubleSlt`, `apGrating`, `apCross`, `apRing`, `apPaint`) свой кусок логики.

---

## Шаг 2. Формула Фраунгофера — "связь объекта и картины"

**Физика:** Если объект освещён плоской волной длины `λ`, и наблюдение ведётся на расстоянии `L` от него в точке `(X, Y)`, то комплексная амплитуда поля выражается так:

```
U(X, Y) = (e^{ikL} · e^{ik(X²+Y²)/2L}) / (i·λL) · ∫∫ t(x, y) · exp(-i·2π·(Xx+Yy)/(λL)) dx dy
```

где `k = 2π/λ`. Двойной интеграл — это и есть **двумерное преобразование Фурье** от маски. Префакторы перед интегралом по модулю равны единице, а интенсивность на экране — это просто:

```
I(X, Y) = |U(X, Y)|²
```

То есть префакторы не влияют на форму картины, только на абсолютную яркость. Поэтому для отображения мы можем игнорировать их и сводить задачу к чистому Фурье-преобразованию маски.

**Условие применимости:** так называемое *число Френеля* должно быть малым:

```
N_F = a² / (λ · L) ≪ 1
```

где `a` — половина характерного размера апертуры. Если `N_F > 0.1`, это уже не дальняя зона, и приближение становится грубым. Программа сама показывает `N_F` и предупреждает.

## Шаг 3. Дискретное преобразование Фурье и БПФ

**Физика → математика:** Непрерывный интеграл считать аналитически слишком сложно для произвольной формы. Мы дискретизируем: разбиваем плоскость объекта на сетку `N × N` пикселей с шагом `dx`, и заменяем интеграл на сумму — это **дискретное преобразование Фурье (ДПФ, DFT)**.

Прямое вычисление ДПФ имеет сложность `O(N⁴)` для двумерной сетки — слишком медленно. Поэтому используется **быстрое преобразование Фурье (БПФ, FFT)** алгоритма Кули–Тьюки по основанию 2 — оно работает за `O(N² log N)`. Для `N = 512` это разница в ~50 раз.

**В коде:** функция `fft1D` (`main.go`) — это БПФ "in-place" над одномерным массивом:

```go
// 1) перестановка в bit-reversed порядке
bitReverse(data)
// 2) log₂N стадий "бабочек"
for size := 2; size <= N; size <<= 1 {
    half := size >> 1
    step := N / size
    for i := 0; i < N; i += size {
        for k := 0; k < half; k++ {
            t := tw[k*step] * data[i+k+half]
            u := data[i+k]
            data[i+k]      = u + t
            data[i+k+half] = u - t
        }
    }
}
```

Здесь `tw` — заранее вычисленные **twiddle factors** `e^{-i·2π·k/N}`. Они вычисляются один раз при первом обращении к `twiddles(N)` и кешируются — синусы и косинусы не пересчитываются на каждый кадр.

## Шаг 4. Двумерное БПФ — "сначала строки, потом столбцы"

**Физика:** двумерное преобразование Фурье можно факторизовать: сначала сделать одномерные FFT по каждой строке матрицы, потом по каждому столбцу. Результат тот же, что от прямого 2D-вычисления.

**В коде:** функция `fft2D` (`main.go`). Самое интересное здесь — **многопоточность**: каждая строка обрабатывается независимо, поэтому их можно гнать параллельно по числу ядер процессора (`runtime.NumCPU()`).

```go
// Фаза 1: FFT по строкам — N горутин
for w := 0; w < nWorkers; w++ {
    wg.Add(1)
    go func(s, e int) {
        defer wg.Done()
        for r := s; r < e; r++ {
            fft1D(data[r*N:(r+1)*N], tw)
        }
    }(start, end)
}
wg.Wait()

// Фаза 2: FFT по столбцам — снова N горутин
```

`sync.WaitGroup` ждёт пока все горутины закончат свою порцию работы — точно тот же паттерн, что в `modeling-1` для суперпозиции витков соленоида.

## Шаг 5. fftshift через шахматный множитель

**Физика → артефакт численного метода:** стандартное БПФ кладёт нулевую частоту (центр картины) в индекс `0`, а высокие частоты — посередине массива. Это неудобно для отображения — нам надо чтобы центр был в центре.

Стандартный приём — операция `fftshift`: после БПФ переставить квадранты массива. Но есть более красивый трюк: если **до** БПФ умножить входной массив на шахматный паттерн `(-1)^(m+n)`, то БПФ автоматически выдаст результат с центром на месте — фактически это математически эквивалентно `fftshift`, выполненный за один проход во время заполнения маски.

**В коде:** в функции `buildAperture`:

```go
if (i+j)&1 == 1 {
    v = -v
}
```

После этого после БПФ нулевая частоты (центральное пятно) автоматически находится в индексе `(N/2, N/2)`. Проверено тестом `TestFFT2DCheckerboardCentersDC`.

## Шаг 6. Интенсивность — `I = |U|²`

**Физика:** глаз и фотодетектор регистрируют не комплексную амплитуду, а интенсивность — квадрат её модуля:

```
I = |U|² = Re(U)² + Im(U)²
```

**В коде:** `recompute()` после БПФ проходит по всем `N²` пикселям параллельно (`parallelFor`) и считает `|c|²`:

```go
parallelFor(n2, func(idx int) {
    c := g.fftBuf[idx]
    re, im := real(c), imag(c)
    g.intensity[idx] = re*re + im*im
})
```

## Шаг 7. Преобразование яркости — "сделать видимыми слабые порядки"

**Физика:** в дифракционной картине центральное пятно может быть в тысячи раз ярче боковых порядков. Если рисовать просто линейно — слабые порядки сольются с фоном.

Применяются два преобразования яркости:

1. **Логарифмическое:** `disp = log(1 + α·I/I_max) / log(1 + α)` — сжимает большой динамический диапазон в видимый,
2. **Гамма-коррекция:** `disp = (I/I_max)^(1/γ)` — растягивает тёмные значения.

**В коде:** функция `transformIntensity` (`main.go`). Переключается клавишей `D`.

## Шаг 8. Цветовое отображение

### Монохромный режим

Одна длина волны, интенсивность через **plasma colormap** — цветовую палитру от фиолетового через красный к жёлтому (та же таблица, что в `modeling-1` для магнитного поля). Точно отражает физику эксперимента с лазером одного цвета.

### RGB-режим

Параллельный расчёт для трёх длин волн (650/550/450 нм). FFT при этом считается **только один раз** (он не зависит от λ — λ входит только в связь между индексом FFT и физической координатой `X`).

Для каждого пикселя экрана `j` физическая координата `X` фиксирована, но индекс FFT, отвечающий за эту координату, разный для разных λ:

```
k_λ = N/2 + (j - N/2) · (λ_max / λ)
```

Для красного (`λ_max`) — `k = j` (как есть). Для синего — индекс растянут (физически синий "сжат" к центру). Используется **билинейная интерполяция** по сетке FFT — функция `bilinear` (`main.go`).

Результат: на решётке хорошо видна **хроматическая дисперсия** — порядки расходятся в радугу, как на CD-диске.

## Шаг 9. Paint mode — рисование произвольной маски

В режиме `apPaint` массив `paintBuf` используется как маска `t(x, y)` напрямую. Мышь в окне:
- ЛКМ ставит `1` (прозрачная область),
- ПКМ ставит `0` (непрозрачная).

Чтобы при быстром движении мыши не оставались "разрывы", функция `paintAt` растеризует **линию** от прошлой позиции к текущей и стампует круглые "капли" вдоль неё (`main.go`).

## Итоговая цепочка

```
амплитудная маска t(x,y) + шахматный сдвиг
        ↓
двумерное БПФ (параллельно по строкам и столбцам)
        ↓
I = |U|² — интенсивность
        ↓
log/gamma — преобразование яркости
        ↓
plasma colormap (mono) или RGB-композиция
        ↓
вывод в окно ebiten
```

## Ключевые вопросы на защиту

**Почему преобразование Фурье?**
Это математическое следствие принципа Гюйгенса–Френеля (каждая точка волнового фронта — источник вторичных волн) в приближении дальней зоны. Поле на экране — сумма вкладов от всех точек объекта с разными фазами, и в пределе большого `L` эта сумма сводится к Фурье-преобразованию.

**Почему БПФ, а не прямое ДПФ?**
Прямое ДПФ на сетке `N×N` имеет сложность `O(N⁴)`. БПФ — `O(N² log N)`. Для `N=512` это разница в ~50 раз — без БПФ интерактивный пересчёт картины был бы невозможен.

**Зачем шахматный множитель?**
Это `fftshift`, выполненный за один проход. Обычный fftshift требует переставить четыре квадранта матрицы после БПФ — лишний проход по памяти. Шахматный множитель в маске даёт тот же эффект бесплатно.

**Что такое число Френеля и почему оно важно?**
`N_F = a²/(λL)` — параметр, показывающий насколько мы "далеко" от объекта. При `N_F ≪ 1` мы в дальней зоне (Фраунгофер). При `N_F ~ 1` — в средней зоне (Френель), там Фурье-формула уже не работает и нужна более полная теория. Программа предупреждает, когда `N_F > 0.1`.

**Почему RGB-режим показывает радугу на решётке?**
Угол отклонения `m`-го порядка `sin θ_m = m·λ/d` зависит от длины волны. Для красного света (большая λ) угол больше — порядок дальше от центра. Для синего — ближе. Поэтому каждый порядок дифракции "разваливается" в спектр от синего к красному.

**Как достигается интерактивность?**
Главные расчёты (FFT, заполнение маски, преобразование интенсивности, рендер пикселей) распараллелены по ядрам процессора через `sync.WaitGroup`. На `N=512` весь пересчёт занимает порядка 10–15 мс — пользователь не успевает заметить задержку между нажатием клавиши и обновлением картины.
