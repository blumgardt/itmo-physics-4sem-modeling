# Физика и код: дифракция Фраунгофера — полная документация

Этот документ — глубокий разбор физики, лежащей в основе программы, и точное отображение этой физики на код в `cmd/diffraction/main.go`. Каждое физическое понятие здесь определяется, выводится математически и подкрепляется фрагментом кода с пояснением, как именно реализация влияет на конечную картину.

---

## 0. Что моделируем

**Дифракция** — это огибание волной препятствия. Когда плоская монохроматическая световая волна с длиной волны `λ` проходит сквозь плоский объект (амплитудный фильтр) и наблюдается на экране, отдалённом на расстояние `L`, на экране формируется не геометрическая тень объекта, а **дифракционная картина** — система светлых и тёмных полос, кольца, точки и т. п.

**Дифракция Фраунгофера** — частный случай, когда экран находится **в дальней зоне** объекта. В этом режиме картина математически связана с самим объектом простой формулой через двумерное преобразование Фурье. Именно этот случай моделирует программа.

В программе задаются:

- `λ` — длина волны падающего излучения (380–780 нм, видимый диапазон);
- `L` — расстояние до плоскости наблюдения (5 см … 5 м);
- `N` — размер расчётной сетки (256, 512 или 1024 — степень двойки);
- `dx` — физический шаг сетки в плоскости объекта (по умолчанию 1 мкм);
- форма и геометрические параметры апертуры (`apW`, `apH`, `apD`, `apNSlits`).

## 1. Физика дифракции

### 1.1 Принцип Гюйгенса–Френеля

Базовый постулат волновой оптики: **каждая точка волнового фронта является источником вторичных сферических волн**. Поле в любой точке за объектом — суперпозиция (сумма с учётом фаз) вкладов от всех точек объекта, через которые волна прошла.

### 1.2 Интеграл Кирхгофа (точная формулировка)

Для плоской волны единичной амплитуды, падающей перпендикулярно объекту, поле в точке `(X, Y)` за объектом на расстоянии `L`:

```
U(X, Y) = (1 / iλ) · ∫∫ t(x, y) · (e^{ikr} / r) · cos α · dx dy
```

где `r = √((X−x)² + (Y−y)² + L²)`, `α` — угол между нормалью к объекту и направлением на точку наблюдения, `k = 2π/λ` — волновое число, `t(x, y)` — амплитудное пропускание объекта.

### 1.3 Приближение Фраунгофера (дальняя зона)

При `L ≫ √((X−x)² + (Y−y)²)` экспоненту в подынтегральном выражении можно разложить:

```
r ≈ L + (X² + Y²)/(2L) − (Xx + Yy)/L + (x² + y²)/(2L) + …
```

Если последним слагаемым `(x² + y²)/(2L)` можно пренебречь (это и есть условие Фраунгофера), интеграл становится двумерным преобразованием Фурье. Полная формула:

```
U(X, Y) = [e^{ikL} · e^{ik(X² + Y²)/(2L)} / (iλL)] · ∫∫ t(x, y) · exp(−i·2π·(Xx + Yy)/(λL)) dx dy
```

Префакторы перед интегралом по модулю равны единице (`|e^{iφ}| = 1`) или константе (`|1/(iλL)| = 1/(λL)`). Они не зависят от `(x, y)` и поэтому не влияют на **форму** картины — только на её абсолютную яркость и фазу.

Подынтегральное выражение — это и есть двумерное преобразование Фурье от маски `t(x, y)` на пространственных частотах:

```
f_x = X / (λL),   f_y = Y / (λL)
```

### 1.4 Число Френеля — критерий применимости

**Число Френеля**:

```
N_F = a² / (λ · L)
```

где `a` — половина характерного размера апертуры. Это безразмерный параметр, показывающий «насколько мы далеко» от объекта.

- `N_F ≪ 1` — дальняя зона, работает формула Фраунгофера;
- `N_F ~ 1` — средняя зона, дифракция Френеля (нужна более полная формула с учётом квадратичной фазы);
- `N_F ≫ 1` — почти геометрическая оптика, дифракции нет.

В программе порог `0.1`: если `N_F > 0.1`, выводится жёлтое предупреждение «far field broken». Код:

```go
a := math.Max(g.apW/2, g.apH/2)
NF := a * a / (g.lambda * g.L)
```

Размер апертуры здесь берётся как половина наибольшего из `apW` и `apH` — характерный масштаб неоднородности объекта.

## 2. Амплитудная маска `t(x, y)`

**Амплитудное пропускание** — комплекснозначная функция, описывающая, как объект преобразует амплитуду проходящей волны в каждой точке. В программе используются только вещественные значения `t ∈ [0, 1]`:

- `t = 1` — точка полностью прозрачна;
- `t = 0` — точка полностью непрозрачна;
- промежуточные значения — частичная прозрачность.

В коде маска хранится как двумерный массив комплексных чисел `apertureBuf []complex128` длиной `N²`. Заполнение делает функция `buildAperture` параллельно по строкам:

```go
for j := s; j < e; j++ {
    y := (float64(j) - cy) * dx
    for i := 0; i < N; i++ {
        x := (float64(i) - cx) * dx
        v := 0.0
        switch apType {
        case apRect:
            if math.Abs(x) <= halfW && math.Abs(y) <= halfH { v = 1 }
        // … остальные пресеты
        }
        if (i+j)&1 == 1 { v = -v }   // шахматный fftshift
        data[j*N+i] = complex(v, 0)
    }
}
```

Здесь `cx = cy = N/2` — индекс центра сетки. Физическая координата `(x, y)` получается из индекса умножением на шаг `dx`. Шахматный множитель — отдельная тема, разобрана в §8.

## 3. Формула Фраунгофера в коде

Сводя физику к численному виду: интенсивность на экране пропорциональна квадрату модуля двумерного преобразования Фурье от маски:

```
I(X, Y) = |U(X, Y)|²  ∝  | F[t](X/λL, Y/λL) |²
```

Префакторы из §1.3 при взятии `|·|²` становятся постоянным множителем `1/(λL)²` и не влияют на форму картины. Поэтому в коде они **никогда не вычисляются** — это сознательное упрощение, основанное на том, что картина впоследствии нормируется на `I_max` (см. §9.2).

## 4. От интеграла к численному расчёту

### 4.1 Дискретизация

Непрерывный двойной интеграл заменяется конечной суммой. Объект разбивается на сетку `N × N` пикселей с шагом `dx`. Значения маски `t(i·dx, j·dx)` — дискретные отсчёты.

### 4.2 Дискретное преобразование Фурье (ДПФ)

```
T(k_x, k_y) = Σ_{i,j} t(i, j) · exp(−i·2π·(k_x·i + k_y·j) / N)
```

где `k_x, k_y ∈ {0, 1, …, N−1}` — индексы выходных бинов.

### 4.3 Быстрое преобразование Фурье (БПФ)

Прямое вычисление ДПФ на сетке `N × N` требует `O(N⁴)` арифметических операций. Для `N = 512` это `~7·10¹⁰` операций — недостижимо для интерактивной программы.

**БПФ** алгоритма Кули–Тьюки сводит сложность к `O(N² log N)`. Для `N = 512` — `~2.4·10⁶` операций, ускорение примерно в 30 000 раз. Без БПФ интерактивный пересчёт картины был бы невозможен.

## 5. Связь параметров сетки и физических координат

### 5.1 Шаг в плоскости наблюдения

По свойствам ДПФ шаг по пространственной частоте равен `1/(N·dx)`. Пространственная частота связана с координатой на экране как `f_x = X/(λL)` (см. §1.3). Перемножая, получаем шаг по `X` в плоскости наблюдения:

```
DX = λ · L / (N · dx)
```

### 5.2 Окно наблюдения

Полный размер видимого окна:

```
W_obs = N · DX = λ · L / dx
```

Заметьте: `W_obs` **не зависит от `N`** — оно определяется только `λ`, `L` и `dx`. При увеличении `N` окно остаётся прежним, но число точек удваивается — видны более тонкие порядки.

В коде окно вычисляется и выводится на экран:

```go
Wobs := lambdaShown * g.L / g.dx
text.Draw(screen, fmt.Sprintf("window: %s", formatLength(Wobs)), ...)
```

**Влияние параметров:** увеличение `λ` или `L` пропорционально растягивает окно — картина «раздувается». Увеличение `dx` (более грубая сетка в объекте) уменьшает окно, но даёт более «крупнозернистый» Фурье-образ.

## 6. БПФ Кули–Тьюки в коде

### 6.1 Twiddle-факторы

**Twiddle-факторы** (поворотные коэффициенты):

```
w_k = e^{−i·2π·k/N},   k = 0, 1, …, N/2 − 1
```

Это комплексные числа на единичной окружности, шаг — `2π/N` по углу. Они кешируются один раз на `N` в карте `twiddleCache`:

```go
func twiddles(N int) []complex128 {
    twiddleMu.Lock()
    defer twiddleMu.Unlock()
    if t, ok := twiddleCache[N]; ok { return t }
    t := make([]complex128, N/2)
    for k := 0; k < N/2; k++ {
        theta := -2 * math.Pi * float64(k) / float64(N)
        t[k] = complex(math.Cos(theta), math.Sin(theta))
    }
    twiddleCache[N] = t
    return t
}
```

Без кеша синусы и косинусы пересчитывались бы на каждый кадр — `O(N² log N)` тригонометрических вызовов в секунду, программа стала бы заметно медленнее. `sync.Mutex` защищает кеш от гонки данных при первом одновременном обращении из нескольких горутин.

### 6.2 Bit-reverse permutation

Итеративный алгоритм Кули–Тьюки получает на вход массив, который должен быть **переупорядочен в битово-обращённом порядке**. Это связано с рекурсивным разбиением: на каждом шаге чётные и нечётные элементы расходятся по разным веткам, и в итоге индекс `i` оказывается на позиции, равной зеркальному отражению его двоичной записи.

Пример для `N = 8` (3-битные индексы):

```
вход:    0   1   2   3   4   5   6   7
двоично: 000 001 010 011 100 101 110 111
зеркало: 000 100 010 110 001 101 011 111
выход:   0   4   2   6   1   5   3   7
```

В коде перестановка делается за один проход:

```go
func bitReverse(data []complex128) {
    N := len(data)
    j := 0
    for i := 1; i < N; i++ {
        bit := N >> 1
        for ; j&bit != 0; bit >>= 1 { j ^= bit }
        j ^= bit
        if i < j { data[i], data[j] = data[j], data[i] }
    }
}
```

Без этой перестановки `fft1D` выдаст результат с **переставленными бинами** — картина «расползётся» хаотически. Проверить легко: закомментировать `bitReverse(data)` в `fft1D` — картина перестанет иметь центральную симметрию.

### 6.3 Бабочка (butterfly) — элементарная операция

После перестановки `log₂ N` стадий объединяют пары:

```go
for size := 2; size <= N; size <<= 1 {
    half := size >> 1
    step := N / size
    for i := 0; i < N; i += size {
        for k := 0; k < half; k++ {
            t := tw[k*step] * data[i+k+half]
            u := data[i+k]
            data[i+k]      = u + t
            data[i+k+half] = u - t
        }
    }
}
```

На каждой стадии:
- `u = a` — «верхняя» точка пары;
- `t = w_k · b` — «нижняя» точка, повёрнутая на twiddle-угол;
- результат: `(u + t, u − t)`.

Это и есть **бабочка** — даёт `O(log N)` стадий вместо одного перемножения `O(N)`. Все операции — in-place (на месте), без дополнительной памяти. Параметр `step = N/size` индексирует twiddle-таблицу: на ранних стадиях используются крупные углы, на поздних — мелкие.

### 6.4 Сложность

- ДПФ: `N²` для одномерного, `N⁴` для 2D на сетке `N×N`.
- БПФ: `N log N` для одномерного, `N² log N` для 2D.
- Для `N = 512`: ускорение `≈ N/log N = 56×` на одном измерении, и **итоговое 2D-БПФ почти в 30 000 раз быстрее прямого ДПФ**.

### 6.5 Почему `N` должно быть степенью двойки

Алгоритм Кули–Тьюки **радикса 2** на каждом шаге делит массив пополам. При `N`, не делящемся на 2 нацело, эта схема ломается. Альтернативы:

- **Смешанный радикс** (например, радикс 3 для `N = 3·2^k`) — сложнее в реализации;
- **Zero-padding** до ближайшей степени двойки — добавляет нулей к маске, но это меняет физический шаг.

В программе разрешены только `N ∈ {256, 512, 1024}`. Переключение — клавишей `N` циклически.

## 7. Двумерное БПФ

### 7.1 Факторизация

Двумерное преобразование Фурье разделяется:

```
T(k_x, k_y) = Σ_j (Σ_i t(i, j) · e^{−i·2π·k_x·i/N}) · e^{−i·2π·k_y·j/N}
```

То есть сначала по `i` (строка), потом по `j` (столбец). Этот факт даёт «строки + столбцы» 2D-БПФ — математически точно эквивалентно прямому вычислению, но позволяет переиспользовать одномерный код.

### 7.2 Параллелизм

Каждая строка обрабатывается независимо — идеальный кейс для параллелизма. В программе на `runtime.NumCPU()` горутин:

```go
nWorkers := runtime.NumCPU()
rowsPerWorker := (N + nWorkers - 1) / nWorkers
var wg sync.WaitGroup
for w := 0; w < nWorkers; w++ {
    start := w * rowsPerWorker
    end := start + rowsPerWorker
    if end > N { end = N }
    if start >= end { break }
    wg.Add(1)
    go func(s, e int) {
        defer wg.Done()
        for r := s; r < e; r++ {
            fft1D(data[r*N:(r+1)*N], tw)
        }
    }(start, end)
}
wg.Wait()
```

`sync.WaitGroup` блокирует поток, пока все горутины не завершатся. Тот же паттерн используется для столбцов (но с буферизацией в `buf` — так как столбцы лежат в памяти неподряд).

**Влияние параллелизма:** на 8-ядерном CPU при `N = 1024` пересчёт картины занимает ~30–60 мс. Без параллелизма — ~240 мс, и интерактивность теряется.

## 8. Центрирование нулевой частоты (fftshift)

### 8.1 Проблема

Стандартное ДПФ кладёт нулевую частоту (центр дифракционной картины) в индекс `0` массива, а высокие частоты — в середину. Это неудобно для отображения: центральное пятно дифракции окажется в углу окна.

### 8.2 Классическое решение — `fftshift`

После БПФ переставить четыре квадранта матрицы:

```
[A B]      [D C]
[C D]  →   [B A]
```

Это требует прохода по всей матрице с копированием — дополнительный `O(N²)` в памяти и времени.

### 8.3 Шахматный множитель — эквивалентный трюк за один проход

Свойство ДПФ: умножение во временной/пространственной области на `e^{iπn} = (−1)^n` сдвигает спектр на `N/2`. Применяя это и по `x`, и по `y`, получаем сдвиг центра в `(N/2, N/2)`:

```
T̃(k_x, k_y) = Σ_{i,j} [(−1)^{i+j} · t(i, j)] · e^{−i·2π·(k_x·i + k_y·j)/N}
            = T(k_x − N/2, k_y − N/2)
```

В коде это умножение делается **во время заполнения маски** — никакого дополнительного прохода нет:

```go
if (i+j)&1 == 1 { v = -v }
```

Корректность проверяется тестом `TestFFT2DCheckerboardCentersDC`: после шахматного множителя и БПФ от постоянной маски пик оказывается ровно в `(N/2, N/2)`.

**Влияние:** если убрать эту строку, центральное яркое пятно дифракции окажется в углу окна, а четыре дольки картины — переставлены по диагонали.

## 9. Интенсивность и нормировка

### 9.1 `I = |U|²`

Глаз и фотодетектор регистрируют не комплексную амплитуду, а интенсивность — квадрат её модуля:

```
I = |U|² = Re(U)² + Im(U)²
```

В коде:

```go
parallelFor(n2, func(idx int) {
    c := g.fftBuf[idx]
    re, im := real(c), imag(c)
    g.intensity[idx] = re*re + im*im
})
```

Параллельно по всем `N²` пикселям через `parallelFor` (та же модель `sync.WaitGroup`).

### 9.2 Нормировка на `I_max`

Абсолютная яркость интенсивности после БПФ не имеет физического смысла: префакторы Фраунгофер-формулы (`1/(λL)²` и фазовые) отброшены. Чтобы картина нормально выглядела на экране независимо от параметров, программа находит максимум по полю и работает с **относительной** интенсивностью `I/I_max ∈ [0, 1]`:

```go
Imax := 0.0
for _, v := range g.intensity {
    if v > Imax { Imax = v }
}
if Imax <= 0 { Imax = 1 }
```

Защитное условие `Imax <= 0` исключает деление на ноль для вырожденного случая «всё чёрное».

**Влияние нормировки:**
- при крупной апертуре центральное пятно даёт огромный пик; без нормировки оно «выгорит» до белого, и боковые порядки утонут в шуме;
- при мелкой апертуре, наоборот, всё стало бы почти чёрным;
- цена — потеря информации об абсолютной яркости (для качественной демонстрации дифракции это не важно).

## 10. Преобразования яркости

Дифракционная картина имеет очень большой динамический диапазон: центральное пятно бывает в `10³–10⁴` раз ярче боковых порядков. Линейное отображение `I/I_max → пиксель` сделает все слабые порядки нулевыми из-за квантования в 8-битном канале (256 градаций).

Реализация — функция `transformIntensity`:

```go
func transformIntensity(I, Imax float64, mode int, gamma, logAlpha float64) float64 {
    if Imax <= 0 { return 0 }
    v := I / Imax
    if v < 0 { v = 0 }
    if v > 1 { v = 1 }
    switch mode {
    case dispLog:
        return math.Log1p(logAlpha*v) / math.Log1p(logAlpha)
    case dispGamma:
        return math.Pow(v, 1.0/gamma)
    default:
        return v
    }
}
```

### 10.1 Линейное (`dispLinear`)

`disp = v = I/I_max`. Видны только самые яркие участки. Полезно, когда нужно показать настоящие пропорции яркости.

### 10.2 Логарифмическое (`dispLog`) с параметром `α`

```
disp = log(1 + α·v) / log(1 + α)
```

Параметр `α = logAlpha` (по умолчанию `1e3`) задаёт **степень сжатия динамического диапазона**:

- при `α → 0` log-преобразование вырождается обратно в линейное (по разложению Тейлора `log(1+x) ≈ x`);
- при `α = 10³` отношение яркости 1:1000 отображается как ~0.5 vs 1.0 в канале — слабые порядки становятся видны.

Используется `math.Log1p(x) = log(1 + x)` для численной устойчивости при малых `x`.

### 10.3 Гамма-коррекция (`dispGamma`) с параметром `γ`

```
disp = v^(1/γ)
```

Тёмные значения «растягиваются» при `γ > 1`, светлые сжимаются. По умолчанию `γ = 2.4`, диапазон `[1.0, 6.0]`, шаг 0.1 (клавиши `G / Shift+G`).

- `γ = 1`: линейная шкала (как `dispLinear`);
- `γ = 2.2…2.4`: стандартная гамма-коррекция для дисплеев (sRGB);
- `γ = 6`: очень агрессивное «вытягивание» тёмных значений.

**Влияние:** `log` агрессивнее `gamma` для типичных значений α и γ — log лучше показывает порядки в 10²–10⁴ раз слабее центра. Gamma более «мягкое», лучше для визуальной эстетики.

Если убрать `transformIntensity` целиком, картина превратится в почти чёрное поле с одной яркой точкой в центре — именно поэтому `log` стоит по умолчанию.

## 11. Цветовое отображение

### 11.1 Plasma colormap (моно-режим)

В моно-режиме одна длина волны, и интенсивность раскрашивается псевдо-цветовой палитрой "plasma" — последовательность от тёмно-фиолетового через красный к жёлтому. Опорные точки (`plasmaStops`) заданы в коде, между ними — линейная RGB-интерполяция:

```go
var plasmaStops = []colorStop{
    {0.00, 13, 2, 33},
    {0.05, 26, 10, 78},
    {0.15, 59, 31, 142},
    // …
    {1.00, 255, 236, 110},
}
```

Поиск интервала и интерполяция:

```go
for i := 0; i < len(plasmaStops)-1; i++ {
    if t <= plasmaStops[i+1].t {
        f := (t - plasmaStops[i].t) / (plasmaStops[i+1].t - plasmaStops[i].t)
        return uint8(plasmaStops[i].r + f*(plasmaStops[i+1].r-plasmaStops[i].r)),
            // … для g и b
    }
}
```

Plasma — perceptually uniform (равномерная по восприятию) палитра, разработанная для научной визуализации. Та же таблица используется в `modeling-1` для визуализации модуля магнитного поля.

### 11.2 RGB-режим

При нажатии `C` программа переходит в режим, имитирующий освещение объекта одновременно тремя длинами волн:

- `λ_R = 650 нм` (красный) → канал R;
- `λ_G = 550 нм` (зелёный) → канал G;
- `λ_B = 450 нм` (синий) → канал B.

БПФ при этом считается **только один раз** (при текущей `λ`, выбранной пользователем), потому что значения `|U|²` сами по себе не зависят от длины волны — `λ` входит только в связь между **индексом** массива и **физической координатой** на экране:

```
X(k) = (k − N/2) · λL / (N·dx)
```

### 11.3 RGB-формула масштабирования

Чтобы получить интенсивность для длины волны `λ_c ∈ {λ_R, λ_G, λ_B}` в физической точке экрана `X`, нужно взять значение из массива по индексу:

```
k_c = N/2 + (j − N/2) · (λ_R / λ_c)
```

За окно наблюдения берётся самая длинноволновая компонента (красная) — это гарантирует, что все три цвета умещаются в окно, без обрезки.

В коде:

```go
lambdas := [3]float64{lambdaR, lambdaG, lambdaB}
for c := 0; c < 3; c++ {
    scale := lambdaR / lambdas[c]
    kx := half + (float64(i)-half)*scale
    ky := half + (float64(j)-half)*scale
    val := bilinear(g.intensity, N, kx, ky)
    t := transformIntensity(val, Imax, g.displayMode, g.gamma, g.logAlpha)
    ch[c] = uint8(t * 255)
}
```

- Для красного `scale = 1` — берём значение из массива «как есть»;
- Для зелёного `scale = 650/550 ≈ 1.18` — выборка идёт чуть дальше от центра;
- Для синего `scale = 650/450 ≈ 1.44` — выборка ещё дальше.

Это и есть отражение факта `sin θ_m = m·λ/d`: меньшая `λ` → меньший угол → ближе к центру в физической координате → дальше от центра в индексе массива (потому что в массиве хранится поле для текущей `λ`, не для трёх).

### 11.4 Билинейная интерполяция

Поскольку `scale` не целое, координаты `(kx, ky)` попадают **между** четырёх соседних отсчётов FFT. Применяется билинейная интерполяция:

```go
func bilinear(I []float64, N int, x, y float64) float64 {
    if x < 0 || y < 0 || x > float64(N-1) || y > float64(N-1) { return 0 }
    i := int(x); j := int(y)
    fx := x - float64(i); fy := y - float64(j)
    i1 := i + 1; j1 := j + 1
    if i1 >= N { i1 = N - 1 }
    if j1 >= N { j1 = N - 1 }
    a := I[j*N+i]; b := I[j*N+i1]
    c := I[j1*N+i]; d := I[j1*N+i1]
    return a*(1-fx)*(1-fy) + b*fx*(1-fy) + c*(1-fx)*fy + d*fx*fy
}
```

Это стандартная двумерная линейная интерполяция: четыре весовых коэффициента в сумме дают `1`, и в углах ячейки результат точно равен соответствующему отсчёту.

**Влияние:** без билинейной интерполяции (округлять `kx, ky` до целого) в RGB-картине появится пиксельный шум, особенно у синего канала, где `scale` далеко от 1. Билинейная сглаживает выборку и даёт чистое наложение каналов.

**Физический результат RGB:** на дифракционной решётке порядки расходятся в радугу (красный дальше от центра, синий ближе) — наблюдаемый эффект на CD-диске.

## 12. Канонические апертуры — формулы и код

Все семь пресетов реализуются в одной функции `buildAperture` через `switch` по типу. Все параметры — в метрах. Управление: клавиши `1`–`6` для пресетов 1–6, `M` для paint mode, `W/H/T` — изменить параметры, `Shift` + клавиша = уменьшить.

### 12.1 Прямоугольное отверстие (`apRect`)

```go
case apRect:
    if math.Abs(x) <= halfW && math.Abs(y) <= halfH { v = 1 }
```

Параметры: `apW` = ширина, `apH` = высота. Маска: `t = 1` внутри прямоугольника `apW × apH` с центром в начале.

**Аналитическая картина:**
```
I(X, Y) ∝ sinc²(apW · X / λL) · sinc²(apH · Y / λL)
```

где `sinc(u) = sin(πu)/(πu)`. Это произведение двух одномерных `sinc²`-функций — следствие факторизации Фурье-интеграла по `x` и `y` для прямоугольной маски.

**Первые нули:** по `X` — на расстоянии `λL/apW` от центра; по `Y` — `λL/apH`.

**Влияние:** уменьшение `apW` расширяет картину по `X` обратно пропорционально (узкий объект → широкий спектр). Тестируется автоматически: `TestFFT2DRectSincZero`.

### 12.2 Круглое отверстие (`apCircle`)

```go
case apCircle:
    if x*x + y*y <= halfW*halfW { v = 1 }
```

Параметр: `apW/2` = радиус. **Картина Эйри**:

```
I ∝ [2 J₁(v) / v]²,   v = π · apW · r / (λL)
```

где `J₁` — функция Бесселя первого рода. Первое тёмное кольцо: `r₁ = 1.22 · λL / apW` — это **критерий Рэлея**, фундаментальный предел разрешения оптических приборов (телескопов, микроскопов).

**Влияние:** уменьшение `apW` раздувает диск Эйри — поэтому телескопы строят большими: больше диаметр → меньше диск Эйри → выше разрешающая способность.

### 12.3 Двойная щель — опыт Юнга (`apDoubleSlt`)

```go
case apDoubleSlt:
    if math.Abs(y) <= halfH {
        if math.Abs(math.Abs(x)-apD/2) <= apW/2 {
            v = 1
        }
    }
```

Условие `|x − apD/2| ≤ apW/2 ∨ |x + apD/2| ≤ apW/2` задаёт две щели шириной `apW` каждая, с центрами на `x = ±apD/2`. То есть `apD` — это **центр-в-центр расстояние** между щелями, `apH` — высота щели.

**Аналитическая картина:**
```
I(X, Y) ∝ sinc²(apW · X / λL) · cos²(π · apD · X / λL)
```

Произведение `sinc²`-огибающей одной щели и интерференционного `cos²`-множителя от двух источников. Период интерференционных полос: `λL/apD`.

**Влияние:** увеличение `apD` сжимает полосы (типичный эффект Юнга); увеличение `apW` сужает огибающую, обрезая дальние полосы.

### 12.4 Дифракционная решётка (`apGrating`)

```go
case apGrating:
    if math.Abs(y) <= halfH {
        totalSpan := float64(apNSlits-1) * apD
        leftEdge := -totalSpan / 2
        rel := x - leftEdge
        if rel >= -apW/2 && rel <= totalSpan+apW/2 {
            idx := math.Floor(rel/apD + 0.5)
            if idx >= 0 && idx < float64(apNSlits) {
                slitCenter := leftEdge + idx*apD
                if math.Abs(x-slitCenter) <= apW/2 {
                    v = 1
                }
            }
        }
    }
```

`apNSlits` одинаковых щелей шириной `apW` через равные промежутки `apD`, симметрично относительно центра. Главные максимумы — в направлениях:

```
sin θ_m = m · λ / apD,   m = 0, ±1, ±2, …
```

В терминах координаты на экране: `X_m = m · λL / apD`.

**Влияние `apNSlits`:** ширина главных максимумов пропорциональна `1/apNSlits` — чем больше щелей, тем острее пики. Это и есть принцип спектроскопа: больше штрихов → выше разрешающая способность по `λ`. Управление — клавиши `[` / `]`, диапазон 2–64.

### 12.5 Крест (`apCross`)

```go
case apCross:
    if (math.Abs(x) <= halfW && math.Abs(y) <= halfH) ||
        (math.Abs(x) <= halfH && math.Abs(y) <= halfW) {
        v = 1
    }
```

Объединение двух перпендикулярных прямоугольников (логическое ИЛИ): горизонтальная полоса `apW × apH` и вертикальная — её же, повёрнутая на 90° (`apH × apW`). Дифракционная картина — наложение двух перпендикулярных `sinc²`-полос (то есть «крестообразная» дифракция от каждой ветви креста).

**Влияние:** если поменять `apW ↔ apH`, маска поворачивается на 90°, картина — тоже.

### 12.6 Кольцо — annulus (`apRing`)

```go
case apRing:
    r2 := x*x + y*y
    if r2 <= halfW*halfW && r2 >= (apD/2)*(apD/2) {
        v = 1
    }
```

Внешний радиус — `apW/2`, внутренний — `apD/2`. Картина — разность двух картин Эйри (внешнего и внутреннего кругов; линейность преобразования Фурье позволяет вычесть одну из другой).

**Влияние `apD`:**
- `apD → 0`: остаётся просто диск Эйри;
- `apD → apW`: остаётся тонкое кольцо, картина асимптотически переходит в осциллирующую функцию `J₀²(π·apW·r/λL)` — модель телескопа с центральным экраном (Кассегрена).

### 12.7 Paint mode (`apPaint`) — произвольная маска

```go
case apPaint:
    if paint != nil {
        v = paint[j*N+i]
    }
```

Маска полностью задаётся пользователем мышью — `paintBuf` содержит значения `t(x, y) ∈ {0, 1}`. Логика рисования — функция `paintAt`:

- координаты мыши переводятся из экранных пикселей в индекс сетки;
- ставится круглый «штамп» радиусом `N/64`;
- от последней позиции к текущей растеризуется отрезок (стандартный алгоритм линии) — иначе при быстром движении мыши останутся «дыры».

Это и есть ответ на исходное требование задачи: «объекты произвольной формы». Все остальные пресеты — лишь тесты для верификации общего метода.

## 13. Видимый спектр 380–780 нм

Параметр `λ` ограничен диапазоном видимого света:

```go
if g.lambda > 780e-9 { g.lambda = 780e-9 }
if g.lambda < 380e-9 { g.lambda = 380e-9 }
```

- `380 нм` — фиолетовая граница (короче — ультрафиолет, глазом не видно);
- `780 нм` — красная граница (длиннее — инфракрасное излучение).

Шаг изменения — `10 нм`. Управление — клавиши `+` / `-`.

**Влияние `λ` на картину:** окно наблюдения `W_obs = λL/dx` пропорционально `λ` — при увеличении длины волны вся картина «раздувается» с тем же шагом сетки. При фиолетовом (`λ = 380 нм`) картина в `780/380 ≈ 2` раза мельче, чем при красном (`λ = 780 нм`), при тех же `L` и `dx`.

## 14. Итоговая цепочка вычислений

```
амплитудная маска t(x, y)           ← buildAperture
       ↓ умножение на (−1)^{i+j}    ← inline в buildAperture: fftshift трюком
двумерное БПФ                       ← fft2D: строки → столбцы, параллельно
       ↓
комплексное поле U(X, Y)            ← в массиве fftBuf
       ↓ |·|²
интенсивность I(X, Y) = |U|²        ← parallelFor: re² + im²
       ↓ деление на I_max
относительная интенсивность ∈ [0,1]  ← в transformIntensity
       ↓ log / gamma / linear
яркость пикселя disp ∈ [0,1]        ← transformIntensity
       ↓
plasma colormap (mono) ИЛИ RGB-выборка с bilinear
       ↓
финальное изображение               ← ebiten.Image, отрисовка
```

Время одного полного пересчёта на современном CPU:

- `N = 256` — менее 5 мс;
- `N = 512` — порядка 10–15 мс (рабочий режим);
- `N = 1024` — порядка 30–60 мс.

Это обеспечивает интерактивность: пользователь нажимает клавишу — картина обновляется без заметной задержки.
